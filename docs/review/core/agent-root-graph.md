## Strengths
- Consistent untrusted-evidence discipline on main LLM calls: instructions privileged, evidence JSON-enveloped as untrustedEvidence, EVIDENCE_POLICY appended — spec-locked.
- Strong loop bounds: explore (wall-clock + maxPages + novelty + sufficiency gate), auth (MAX_STEPS + no-progress guard), repair (maxRetries + byte-identical detection), recursionLimit with actionable mapping.
- Failure contract genuinely enforced: typed RaikenErrors instead of prose; grounding contradictions hard-block while unverified locators only warn; best-draft selection.
- Thoughtful resume machinery: durable HITL workflows re-execute save/run/repair without re-running the graph; discovery-driven authenticated-entry recovery.
- Careful prompt engineering with rationale comments (baseURL/sub-path rule, template-selector vs live-DOM precedence, assertion-polarity guard).

## Test-coverage observations
- Nothing exercises runToolAgent itself: streaming ordering, abort mid-run, generator abandonment (the dangling-promise path), recursion-limit mapping, draftStreamed suppression.
- detectInterruption has NO node-level spec (only its utils) — exactly why the dead paused_reason read survived; stale-session/no-session branches uncovered.
- No navigate-node URL-precedence spec (the high finding), no explore-loop spec.
- generate-tests-node.spec misses pass-2-worse best-draft selection, polarity pass, streaming failure, streamed-vs-saved divergence.
- prompt-messages.spec covers the injection boundary but not truncation caps (12/8000) or role mapping.
- No spec pins the token-budget contract.

## Verdict
**needs fixes** — three high-severity defects on realistic paths (dead manual-login session save; reasoning-model budget contract not applied to interactive generation; stale-URL precedence) plus several medium cancellation/state issues; no data-corruption blocker, and the architecture (evidence boundaries, loop bounds, failure contract) is fundamentally sound.
