## Strengths
- Disciplined never-throw tool contract: every execute wraps its body and returns a ToolResult (one exception found); errors carry context via formatToolError.
- Containment-by-default: all file-touching tools route through safePath → resolvePathWithinProject (realpath-canonicalizing, symlink-aware — genuinely careful).
- Auth-state hygiene: validated, atomic, 0600 writes; WeakMap-tracked auth precondition forces a browser restart whenever the auth context changes (spec-locked).
- Destructive actions triple-gated: clearDiscoveryData requires a per-request authorization predicate + abort check + lease with error handling.
- The contract spec locks registry composition, disjoint names, schema surfaces, HITL branches; hidden params (_repairVerification/_overwriteTarget) are graph-injected, never model-reachable.

## Test-coverage observations
- executeTestRun under OPERATION_BUSY — nothing verifies runTest returns a ToolResult instead of throwing.
- saveFile auto-approved branch writing a NON-test path (package.json) — no spec pins allow/reject.
- URL scheme handling (file://, javascript:, data:) — untested.
- readFile/listDirectory access to .raiken/ internal state — untested.
- shared/site-db-cache.ts has NO specs at all: parent-depth linking, backwards link verification, LRU eviction + close, signal-handler side effect.
- snapshotAfterAction changed-without-prevUrl semantics; URL-credential redaction; closeBrowser/startBrowser lease/force-restart edges; waitForElement timeout bounds — all untested.

## Verdict
**minor fixes needed** — the tool layer is well-engineered with clean lifecycle, redaction, and traversal containment, but four guardrail gaps (uncaught lock-conflict rejection, unrestricted auto-save targets, unschemed navigation URLs, .raiken readability) should be closed before trusting it with autonomy=auto settings.
