## Strengths
- Evidence-first query design: per-reason provenance/confidence with run-ci layering — the explainability contract is real.
- Watch-mode persistence is unusually careful: id-preserving upsert protecting the embeddings FK + stranded vec rows, explicit vec_embeddings cleanup (no FK on virtual tables), full removeFile cascade, per-file try/catch in saveGraph.
- masking/sfc/source-analysis are small, sharp modules — line-preserving masking gives SFCs and unparsable templates real symbols.
- Cache-growth discipline: bounded caches with eviction, 2MB per-file cap, batched traversal.
- Good regression specs where they exist: unlink ordering, unknown-path removal, oversize skip, SFC indexing.

## Test-coverage observations
- GraphQueryService has ZERO specs — evidence merging, confidence aggregation, source_map vs dependency vs calls/renders, explain() — the layer `raiken ci` depends on.
- ProjectContext has ZERO specs — initialize()'s DB-merge (the high-sev bug), refresh paths, handleWatchEvent sync untested.
- No tests for alias loading (the dead path), resolveImports/generatePossiblePaths, or tree-hash recompute (incl. cycles).
- No EntryPointDetector specs. Parity/repo specs don't cover keyword_index lifecycle across remove/watch, getAffectedTests via graph_edges, or the static_ast-preserving replaceFileEdges invariant.

## Verdict
**needs fixes** — two realistic-path correctness bugs (immortal stale keyword rows polluting every search; alias extraction that provably never matches) plus an unwired runtime signal undermine the graph's core promises, though the persistence and watch plumbing itself is solid.
